# TongLink Studio 项目介绍

> 一个面向 IT/OT 场景的开源数据采集与编排平台。用 DAG 画布把「采集 → 处理 → 输出」串起来，让工业现场数据与业务系统之间的数据链路可视化、可复用、可观测。
>
> 项目计划以 **MIT 协议** 发布到 GitHub。本文描述项目的目标、功能与边界；技术细节见 [`ARCHITECTURE.md`](ARCHITECTURE.md)，部署操作见 [`DEPLOYMENT.md`](DEPLOYMENT.md)。

---

## 1. 为什么做这个项目

在工厂与企业的实际数据场景中，常见的问题是：

- 数据源碎片化：OPC UA、Modbus、S7 PLC、MQTT、HTTP、各类数据库同时存在，接入方式各不相同。
- 采集逻辑靠脚本堆砌：维护困难，无法复用，执行失败也难以追溯。
- 缺少统一的运维视角：谁在采、多久采一次、采了多少条、什么时候失败，往往要翻多个系统。
- 编排工具要么偏 IT（SaaS 自动化），要么偏 OT（组态软件），缺少一个既懂工业协议、又能像现代低代码平台那样编排的开源方案。

TongLink Studio 试图用一套统一的 DAG 编排模型解决这些问题：把协议接入、数据变换、代码扩展、输出分发都抽象成**节点**，用画布连接，用执行日志记录每一次运行。

## 2. 核心功能

### 2.1 数据看板

- 流程运行状态、下次执行时间、采集记录数、成功率、最近运行时间。
- 24 小时 / 7 天 / 30 天趋势、采集条数柱状图、状态分布图。
- 数据异常点标记，点击可直接发起 AI 分析。
- 点击流程名跳转到对应流程的编排画布。

### 2.2 数据源管理

- IT 数据源：HTTP/REST、OAuth 2.0、MySQL、Oracle、PostgreSQL、SQL Server、MongoDB、Kafka、MQTT。
- OT 数据源：OPC UA、Modbus TCP 已开放真实读写——数据源抽屉可现场测试连通性（Modbus 读寄存器 / OPC UA 读服务端状态节点），节点执行器通过统一工业协议网关对设备读写；S7comm 暂未开放。
- Modbus 节点支持保持寄存器 / 输入寄存器 / 线圈 / 离散输入的读取与保持寄存器 / 线圈写入，起始地址兼容 0 基与 40001/30001/00001/10001 传统写法；OPC UA 节点支持按 nodeId 读写，写入类型自动跟随点位现有类型。测试项目内置 4 条工业场景流程（Modbus/OPC UA 各读写一条）。
- 新建 / 编辑表单字段随连接类型变化；数据库连接可填「主机 + 端口」（库名可选，MySQL/PostgreSQL 允许连接实例后再指定库）或直接粘贴完整 JDBC URL，抽屉里可保存前测试连接。Oracle/SQL Server 仍需填写服务名或库名。
- 支持单条按名称导出与全部导出，支持 JSON 导入。

### 2.3 流程编排

- 项目 → 流程两级管理，顶部下拉选择项目并显示各项目流程数。
- DAG 画布：**单击选中并拖动，双击打开属性配置**，端口拖拽连线，平移缩放，网格吸附，撤销重做。
- 节点库涵盖触发器、数据源、代码与逻辑、输出四大类；支持节点独立安装。
- 流程 JSON 导入 / 导出（按流程名称命名）。
- **定时触发**支持每 N 秒、每 N 分钟、Cron 表达式三种模式。
- 节点配置中的连接与认证字段统一为**下拉选择已建数据源**；数据源按节点协议自动过滤。数据源本身由一种连接类型定义，连接地址与认证信息在同一张表单里填写，不再重复。

### 2.4 节点类型

| 类别 | 节点 |
|---|---|
| 触发器 | 手动触发、定时触发、事件订阅（MQTT / Kafka） |
| 数据源 | MQTT、HTTP、Kafka、MySQL、Oracle、PostgreSQL、SQL Server、MongoDB |
| 代码与逻辑 | Node 代码、Python 代码、条件分支、数据合并、延时等待 |
| 输出 | 写入时序库、HTTP 推送、告警通知、飞书多维表格 |

数据库支持 `select / insert / update / delete / execute`（MongoDB 为 find/insert/update/delete/aggregate），属性字段随操作类型联动。飞书多维表格支持新增、更新、查询、删除记录与字段映射。

告警通知支持企业微信、钉钉、邮件、通用 Webhook 四种渠道：选择「邮件」时引用「邮件 SMTP」数据源（服务器、端口、SSL/STARTTLS、发件账号与授权码），在「Webhook 地址 / 收件人」填收件邮箱；标题与正文支持 `{{ $json.字段 }}` 模板，并可设置重复告警抑制分钟数。未配置凭据或目标为占位地址时只生成模拟回执，便于无第三方账号时演示编排。

### 2.5 变量与数据源

- 变量独立成页，明文保存并按项目作用域隔离；数据源独立成页，按连接类型渲染一张表单。
- 数据源表单里的密码类字段使用 AES-256-GCM 加密，API 只返回掩码，永不回显明文。
- 类别与协议由连接类型自动推导，用户不再重复填写；节点通过下拉引用数据源，不在节点里硬编码秘密。

### 2.6 执行日志

- 多维筛选的执行列表，节点级时间线、状态、耗时、输入 / 输出 JSON。
- 真实感错误信息（Python `ValueError`、连接拒绝、超时等）与重试记录。
- 失败详情可一键发起 AI 诊断。

### 2.7 AI 能力

- 自然语言生成流程：返回结构化流程 JSON，作为草稿加载到画布，用户确认后才保存发布。
- 执行失败诊断：输出根因、证据、修复步骤的结构化诊断卡。
- 数据异常问答：对采集数据做异常检测并支持自然语言提问。
- 独立 AI 助手页 + 流程编排 / 执行日志 / 看板三处嵌入入口。

### 2.8 节点插件

- 节点管理抽屉可安装 / 卸载内置扩展节点，也可导入本地节点包 JSON/ZIP。
- 节点包由 `manifest.json` + `schema.json` + 图标 + 国际化 + 运行产物组成。
- 安装后前端节点库与属性表单自动出现新节点，无需修改前端代码。

## 3. 核心概念

| 概念 | 说明 |
|---|---|
| 项目（Project） | 流程的分类单元；先建项目再建流程，所有页面按当前项目过滤 |
| 流程（Flow） | 一张 DAG 图，包含节点、连线与调度设置；草稿与已发布版本分离 |
| 节点（Node） | 流程中的一个执行单元，由类型、子类型、版本号与配置组成 |
| 数据源（Datasource） | 一个可复用的连接配置，由连接类型决定类别与协议，连接与认证参数同在一张表单；节点通过引用使用 |
| 连接类型（Credential Type） | 决定数据源表单字段、类别与协议；密码类字段加密存储，接口只回掩码 |
| 变量（Variable） | 环境相关的配置值，支持作用域 |
| 执行（Execution） | 一次手动或定时运行；包含每个节点的状态、耗时、输入输出与日志 |
| 节点包（Node Package） | 可独立开发、安装、升级的节点扩展单元 |

## 4. 技术栈一览

- 前端：Vue 3 + TypeScript + Vite + Pinia + Element Plus + **`@vue-flow/core`（DAG 画布）** + CodeMirror 6 + ECharts。
- 后端：Java 21 LTS + Spring Boot 3.5.x + Spring Security + MyBatis-Plus + Quartz。
- 存储：PostgreSQL 16 + TimescaleDB（标准 / 队列模式），SQLite（轻量单容器模式）。
- 队列：默认进程内队列；队列模式切 Redis Stream。
- 代码运行：Task Runner 双模式，默认子进程、可选独立容器。
- 协议：Apache PLC4X（OPC UA / Modbus / S7）、Eclipse Paho（MQTT）。
- AI：Spring AI，支持 OpenAI 兼容接口与本地 Ollama。

## 5. 设计参考与开源边界

- 交互范式（DAG 画布、节点属性面板、执行日志、类型化连接管理）采用业界常见的工作流设计；画布使用 MIT 协议的 `@vue-flow/core`，代码节点采用 Task Runner 的双模式设计。
- 部署形态采用渐进方式：单容器轻量起步，按需增加数据库、队列、Worker、Runner。
- **本项目以 MIT 协议发布**，不复制任何第三方项目的代码、品牌或许可条款；所有界面文案、模拟数据与实现均为独立编写。
- 同时参考 Node-RED、EMQX、EdgeX 等开源 IIoT 项目的协议接入思路。

## 6. 适用与不适用场景

**适用**

- 工厂 / 产线的设备数据采集与上报。
- IT 系统（数据库、HTTP、Kafka）与 OT 系统之间的数据同步。
- 需要把采集逻辑可视化、可审计、可复用的中小团队。

**暂不适用**

- 需要毫秒级实时流处理的场景（本项目是任务型编排，不是流处理引擎）。
- 需要多租户 SaaS 计费与开箱即用的公有云市场（不在首版范围）。
- 需要在不可信多租户环境中运行任意用户代码且要求强安全隔离（需启用外部 Runner 并做额外加固）。
